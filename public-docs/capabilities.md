# Capabilities and evidence

Use this matrix to scope what you can expect from a Team Run. It records the CC source checkout and proof available on September 7, 2026. A passing run at a linked revision is evidence for that configuration, not certification of every model, provider version, or host.

For installation and update availability, use the [distribution and compatibility guide](https://github.com/consolidated-compute/consolidated-compute/blob/main/public-docs/index.md#distribution-and-compatibility). To start a run, follow the [first-Team walkthrough](https://github.com/consolidated-compute/consolidated-compute/blob/main/public-docs/github-work.md).

## Read support and evidence separately

| Term                        | What it establishes                                                                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Architecture support        | CC can use the existing Paseo adapter and shared Team contracts. It does not prove a particular provider launch or security boundary.                        |
| Provider mapping            | CC understands a specific provider-native launch control. The selected host must still validate its actual provider, model, options, and Workspace.          |
| Enforced (`enforced`)       | The frozen preview identifies a fail-closed provider restriction for that dimension. This is a configuration-derived claim, not a new sandbox created by CC. |
| Policy only (`policy_only`) | Provider permission policy or guidance applies, but CC does not claim a fixed technical restriction for that dimension.                                      |
| Unavailable (`unavailable`) | CC cannot establish the restriction from this launch. It does not mean access is denied or that the provider has no such capability outside CC.              |
| Not yet tested              | No matching real-provider/platform proof is recorded here. This evidence label is separate from the three preview states.                                    |

Read the actual role-by-role preview before Start. An enforced delegation restriction does not imply enforced filesystem, network, or shell restrictions. A historical run retains its accepted posture; current Profile edits cannot upgrade that history. The [Team contract](https://github.com/consolidated-compute/consolidated-compute/blob/main/docs/teams.md#run-acceptance) owns admission and snapshot semantics.

## Provider coverage

The providers below have Paseo runtime integration. Ordinary sessions and sequential Teams do not require the supervised native-delegation gate, but still depend on the selected host's provider availability and valid launch configuration. Supervised Teams additionally require every role to pass that gate and the [daemon authentication requirements](https://github.com/consolidated-compute/consolidated-compute/blob/main/public-docs/index.md#set-up-daemon-authentication-before-starting).

| Harness                                  | Supervised launch mapping in CC                                                                            | Recorded real Team proof                                                                                                                                  |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex                                    | Available when the frozen preview establishes native delegation is disabled; auto-review does not qualify. | macOS: filesystem boundary, sequential and supervised Teams, and GitHub Work. See the evidence ledger below.                                              |
| Claude Code                              | Available for the exact built-in provider with its native delegation tools explicitly denied.              | Not yet tested through the full Team path; [#127](https://github.com/consolidated-compute/consolidated-compute/issues/127) owns the second-harness proof. |
| OpenCode                                 | Available for the exact built-in provider with a fail-closed native task-delegation deny.                  | Not yet tested through the full Team path.                                                                                                                |
| GitHub Copilot, Pi, Oh My Pi             | Unavailable: no CC native-delegation enforcement mapping, so supervised admission rejects these launches.  | Not yet tested through the full Team path.                                                                                                                |
| Custom/derived providers and generic ACP | Unavailable: a derived provider does not inherit the built-in provider's posture or security presets.      | Not yet tested; extending a tested provider is not equivalent evidence.                                                                                   |

The [provider registry](https://github.com/consolidated-compute/consolidated-compute/blob/main/packages/server/src/server/agent/provider-registry.ts) owns which mappings and presets are exposed. [Provider-native options](https://github.com/consolidated-compute/consolidated-compute/blob/main/docs/providers.md#provider-native-session-options) owns the accepted configuration contract. These rows are not a claim of identical provider semantics.

## What the preview can claim

These are the current CC mappings, not default permissions or proof that every listed restriction was exercised against a real provider. Missing or incompletely frozen controls remain unavailable.

| Dimension         | Codex                                                                                                                           | Claude Code                                                                             | OpenCode                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Filesystem writes | Enforced for the fail-closed read-only or fully scoped Workspace-write launch; approval escape paths can make this policy only. | Unavailable in CC's current projection, including launches with native sandbox options. | Unavailable in CC's current projection.                                           |
| Network access    | Enforced only for the fully frozen network-deny launch without approval escape; an approvable deny is policy only.              | Unavailable in CC's current projection.                                                 | Unavailable in CC's current projection.                                           |
| Tool/shell use    | Approval policy can be policy only; disabling approvals does not establish a tool/shell boundary.                               | Recognized permission modes are policy only; bypass mode does not establish a boundary. | Unavailable in CC's current projection; native permissions are not an OS sandbox. |
| Native delegation | Enforced only for a qualifying explicit deny.                                                                                   | Enforced only for a qualifying explicit deny.                                           | Enforced only for a qualifying explicit deny.                                     |

The provider-owned projections are [Codex](https://github.com/consolidated-compute/consolidated-compute/blob/main/packages/server/src/server/agent/providers/codex/security-posture.ts), [Claude](https://github.com/consolidated-compute/consolidated-compute/blob/main/packages/server/src/server/agent/providers/claude/security-posture.ts), and [OpenCode](https://github.com/consolidated-compute/consolidated-compute/blob/main/packages/server/src/server/agent/providers/opencode/security-posture.ts). Other providers currently use the [unavailable projection](https://github.com/consolidated-compute/consolidated-compute/blob/main/packages/server/src/server/agent/provider-security-posture.ts).

The Codex filesystem proof below does not also prove network isolation. None of these facts certifies secret isolation, GitHub least privilege, deployment access, host containment, or isolation of every daemon/MCP tool. Role instructions and Artifacts do not grant authority. Review the [operator security guidance](https://github.com/consolidated-compute/consolidated-compute/blob/main/public-docs/github-work.md#review-the-security-preview) for the shared-host boundary.

## Platform coverage

Keep the client surface separate from the daemon/provider host. A phone connected to a macOS daemon does not prove the provider on iOS, and a Linux CI pass does not prove a credentialed Linux Team Run.

| Client / execution host                       | Recorded scope                                                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Browser / macOS daemon                        | Real GitHub Work and Codex/Spark execution; see #151 above.                                                                                                                    |
| Real Electron / macOS daemon                  | Real GitHub Work execution and operator PR readback; see #152/#153 above. Source/dev runtime, not packaged installation or updater QA.                                         |
| Browser or Electron / Windows or Linux daemon | No equivalent real-provider GitHub Work proof recorded here. Credential-free CI is separate evidence.                                                                          |
| Docker daemon                                 | No equivalent real-provider Team boundary proof recorded here.                                                                                                                 |
| iOS and Android clients                       | End-to-end native matrix remains deferred in [#64](https://github.com/consolidated-compute/consolidated-compute/pull/64). Compact browser coverage is not native-device proof. |

Publication of the GitHub Work Team Run's generated changes remains unproved by that specific execution path. Second-harness validation remains in #127; native closure remains in #64. Use these limits when describing the product, rather than extending one successful provider/platform result to every supported combination.
